# Quick Definition

An application dependency graph is a diagram, generated from app files, showing how the OTP applications in a code base depend on one another.

# Core Definition

From Chapter 1, section "Dependencies": "All applications have dependencies, and these dependencies will have their own dependencies. OTP applications usually share no state between them, so it's possible to know what bits of code depend on what other bits of code by looking at the app file only." A diagram generated from app files shows the structure: ovals are applications, rectangles are library applications, with common applications like `kernel` and `stdlib` ignored.

# Prerequisites

- `app-file` — the graph is generated by reading app files.
- `otp-application` — the graph's nodes are applications.

# Key Properties

1. Buildable purely from app files because OTP applications usually share no state — dependency is encoded in the `applications` tuple.
2. In the book's diagram convention, ovals are applications and rectangles are library applications.
3. Common applications such as `kernel` and `stdlib` are typically omitted to keep the graph readable.
4. Generated via `recon`'s script directory: `escript script/app_deps.erl` (this script depends on graphviz).
5. The `observer` application shows similar hierarchies, but for individual supervision trees rather than application dependencies.

# Construction / Recognition

Find `recon`'s script directory and run `escript script/app_deps.erl` to produce a diagram. Combine this cross-application view with each application's short `description` to draw a rough map of where everything lives.

# Context & Application

Used when diving into a large code base (such as a release with many applications) to get a high-level map before drilling into individual supervision trees.

# Examples

From Chapter 1, section "Dependencies": the book shows a "Dependency graph of riak_cs, Basho's open source cloud library," noting "The graph ignores dependencies on common applications like kernel and stdlib. Ovals are applications, rectangles are library applications."

# Common Errors

- Expecting `app_deps.erl` to run without graphviz installed — the script depends on it.
- Confusing the application dependency graph with a supervision tree; `observer` shows the latter.

# Common Confusions

- The dependency graph reflects compile/start-time application dependencies (from app files), not runtime message flows between processes.
