# Quick Definition

`erl` is the command used to start an Erlang runtime system, accepting command-line arguments that control boot scripts, code loading mode, code paths, and other runtime behavior.

# Core Definition

The `erl` command starts an Erlang runtime system from the operating system shell. It accepts a number of command-line arguments that configure the runtime, including `-boot` (to specify a boot script), `-mode` (to select embedded or interactive code loading), `-pa`/`-pz` (to extend the code path), and `-init_debug` (to trace boot script interpretation). Application programs can access the values of command-line arguments via the `init` module functions `get_argument/1`, `get_arguments/0`, and `get_plain_arguments/0`.

Source: "Starting the System" section of OTP System Principles documentation (Ericsson AB).

# Key Properties

1. Primary entry point for starting the Erlang runtime system
2. Accepts command-line flags that configure runtime behavior
3. Key flags include `-boot`, `-mode`, `-pa`, `-pz`, `-init_debug`
4. If no `-boot` flag is specified, defaults to `ROOT/bin/start` boot script
5. Command-line argument values are accessible programmatically via the `init` module
6. Documented in the ERTS application reference manual

# Construction / Recognition

## To Construct/Create:
1. Open an operating system shell
2. Type `erl` with desired command-line flags
3. Example: `erl -boot start_sasl -pa /path/to/my/code`

## To Identify/Recognize:
1. The `erl` command is an OS-level executable in the Erlang/OTP installation
2. It produces the familiar Erlang/OTP banner and Eshell prompt on startup

# Context & Application

The `erl` command is used in development to start interactive Erlang sessions, and in production to start runtime systems with specific boot scripts and configurations. Understanding its command-line flags is essential for controlling which applications start, how code is loaded, and how the system is configured. In production, `erl` is typically wrapped in start scripts generated by release tools.

# Examples

**Example 1** (System Principles section): Starting with a specific boot script:

```text
% erl -boot start_all
```

**Example 2** (System Principles section): Using `-init_debug` to trace boot script interpretation:

```text
% erl -init_debug
{progress,preloaded}
{progress,kernel_load_completed}
{progress,modules_loaded}
{start,heart}
{start,logger}
  .
  .
  .
```

**Example 3** (System Principles section): Extending the code path:

```text
% erl -pa /home/arne/mycode
```

**Example 4** (System Principles section): Starting in embedded mode:

```text
% erl -mode embedded
```

# Common Errors

- **Error**: Specifying the `.boot` extension with the `-boot` flag (e.g., `erl -boot start_clean.boot`).
  **Correction**: The `.boot` extension must be omitted: `erl -boot start_clean`.

- **Error**: Not specifying a boot script and expecting SASL to be available.
  **Correction**: The default boot script depends on the installation choice. If `start_clean` was chosen as default, SASL will not be loaded. Use `erl -boot start_sasl` explicitly.

# Common Confusions

- **Confusion**: The `erl` command and `erl` shell are the same thing.
  **Clarification**: `erl` is the OS-level command that starts the runtime system. The Erlang shell (Eshell) is a process that runs within the started runtime system, providing an interactive REPL.
