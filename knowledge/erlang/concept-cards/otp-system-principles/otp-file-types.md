# Quick Definition

Erlang/OTP defines a set of standard file types with specific extensions that serve distinct roles in development, configuration, and release management.

# Core Definition

As presented in OTP System Principles, the following file types are defined in Erlang/OTP:

| File Type                 | Extension   | Documented in            |
|---------------------------|-------------|--------------------------|
| Module                    | `.erl`      | Erlang Reference Manual  |
| Include file              | `.hrl`      | Erlang Reference Manual  |
| Release resource file     | `.rel`      | rel in SASL              |
| Application resource file | `.app`      | app in Kernel            |
| Boot script               | `.script`   | script in SASL           |
| Binary boot script        | `.boot`     | -                        |
| Configuration file        | `.config`   | config in Kernel         |
| Application upgrade file  | `.appup`    | appup in SASL            |
| Release upgrade file      | `relup`     | relup in SASL            |

# Prerequisites

This is a foundational concept with no prerequisites.

# Key Properties

1. `.erl` — Erlang source module files, the primary unit of code.
2. `.hrl` — Header/include files for shared record definitions, macros, and type specs.
3. `.rel` — Release resource files that define a release (applications and versions).
4. `.app` — Application resource files that describe an OTP application.
5. `.script` — Human-readable boot script files generated from `.rel` files.
6. `.boot` — Binary (compiled) boot scripts used by the runtime system at startup.
7. `.config` — System configuration files for application environment variables.
8. `.appup` — Application upgrade files describing how to upgrade/downgrade between versions.
9. `relup` — Release upgrade files (no dot prefix) describing release-level upgrade instructions.

# Construction / Recognition

## To Construct/Create:
1. `.erl` and `.hrl` files are written by developers.
2. `.app` files are written by developers or generated by build tools (e.g., rebar3).
3. `.rel` files are written to define a release.
4. `.script` and `.boot` files are generated using `systools:make_script/1,2`.
5. `.config` files are written to configure application environments.
6. `.appup` files are written for application upgrades.
7. `relup` files are generated using `systools:make_relup/3,4`.

## To Identify/Recognize:
1. Look at the file extension.
2. Note that `relup` is a filename (not an extension) — it has no dot prefix.

# Context & Application

These file types form the structural backbone of Erlang/OTP development and deployment. Source files (`.erl`, `.hrl`) are used during development. Resource files (`.app`, `.rel`) describe the application and release structure. Boot files (`.script`, `.boot`) control system startup. Configuration files (`.config`) parameterize the runtime. Upgrade files (`.appup`, `relup`) enable hot code upgrades in running systems.

# Common Errors

- **Error**: Confusing `.script` and `.boot` files — editing a `.boot` file as if it were human-readable.
  **Correction**: `.boot` is a binary format; edit the `.script` file or regenerate from the `.rel` file.

- **Error**: Using a dot prefix for `relup` (e.g., `.relup`).
  **Correction**: The release upgrade file is named `relup` with no dot prefix, unlike all other OTP file types.

# Common Confusions

- **Confusion**: Thinking `.app` and `.rel` files serve the same purpose.
  **Clarification**: `.app` describes a single application (modules, dependencies, startup). `.rel` describes a complete release (which applications and versions comprise the system).
