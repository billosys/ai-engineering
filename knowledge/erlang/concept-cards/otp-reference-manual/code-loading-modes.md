# Quick Definition
The Erlang code server supports two loading strategies: interactive mode (default), where code is searched and loaded on first reference, and embedded mode, where all code is loaded at startup from a boot script.

# Core Definition
The Erlang Reference Manual states: "The code server loads code according to a code loading strategy, which is either _interactive_ (default) or _embedded_. In interactive mode, code is searched for in a _code path_ and loaded when first referenced. In embedded mode, code is loaded at start-up according to a _boot script_." (Compilation and Code Loading, "Code Loading" section).

# Prerequisites
- **code-server** -- The code server implements both loading strategies

# Key Properties
1. Two modes: interactive (default) and embedded
2. Interactive mode: lazy loading -- modules loaded on first reference via code path search
3. Embedded mode: eager loading -- all modules loaded at startup from a boot script
4. Interactive mode is used during development
5. Embedded mode is used in production/deployed systems for predictability
6. The code path is a list of directories searched for `.beam` files (in interactive mode)
7. Boot scripts specify exactly which modules to load (in embedded mode)

# Construction / Recognition
## To Construct/Create:
1. Interactive mode is the default; no special configuration needed
2. Embedded mode is started with: `erl -mode embedded`
3. Boot scripts are generated by the release tools

## To Identify/Recognize:
1. Check with `code:get_mode()` which returns `interactive` or `embedded`

# Context & Application
Interactive mode is ideal for development because it automatically finds and loads modules as they are needed, supporting rapid iteration. Embedded mode is preferred for production systems because it ensures all required modules are loaded at startup, making the system's behavior predictable and catching missing modules early. OTP releases use embedded mode to guarantee that the system starts with all necessary code.

# Examples
**Example 1** (interactive mode, development):
```erlang
%% Module loaded automatically on first call
1> my_module:hello().
"Hello, World!"
```

**Example 2** (embedded mode startup):
```text
% erl -mode embedded -boot my_release
```

# Common Errors
- **Error**: Missing modules in embedded mode causing startup failure
  **Correction**: Ensure the boot script includes all required modules; use the OTP release tools to generate correct boot scripts

- **Error**: Assuming modules are pre-loaded in interactive mode
  **Correction**: In interactive mode, a module is not loaded until first referenced; `code:is_loaded(Module)` returns `false` until then

# Common Confusions
- **Confusion**: Thinking interactive mode means interpreted execution
  **Clarification**: Both modes execute compiled BEAM bytecode. "Interactive" refers only to the loading strategy (lazy, on-demand), not to interpretation.
