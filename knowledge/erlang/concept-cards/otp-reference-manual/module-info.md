# Quick Definition
The `module_info/0` and `module_info/1` functions are automatically inserted into every compiled module by the compiler. They provide runtime access to module metadata including exports, attributes, compile information, and the module's MD5 checksum.

# Core Definition
The Erlang Reference Manual states: "The compiler automatically inserts the two special, exported functions into each module: `Module:module_info/0` and `Module:module_info/1`. When called, these functions retrieve information about the module." (Modules, "module_info/0 and module_info/1 functions" section).

# Prerequisites
- **erlang-module** -- module_info functions are auto-generated for every module
- **export-attribute** -- module_info functions are automatically exported

# Key Properties
1. Automatically inserted by the compiler -- no source code needed
2. Both functions are automatically exported
3. `module_info/0` returns a list of `{Key, Value}` tuples
4. `module_info/1` takes a key atom and returns a single piece of information
5. Available keys for `module_info/1`: `module`, `attributes`, `compile`, `md5`, `exports`, `functions`, `nifs`
6. The `attributes` list becomes empty if the module is stripped with `beam_lib:strip/1`
7. The `compile` list also becomes empty after stripping

# Construction / Recognition
## To Construct/Create:
These functions are auto-generated; no construction is needed.

## To Identify/Recognize:
1. Call `Module:module_info()` or `Module:module_info(Key)` on any loaded module
2. These functions appear in a module's export list even though they are not in the source

# Context & Application
The module_info functions are essential for runtime introspection. They are used by tools, debuggers, and code management systems to query module properties. Common uses include: listing a module's exported functions, checking compile-time options, retrieving custom attributes, and verifying module identity via MD5 checksums.

# Examples
**Example 1** (using module_info/1 with various keys):
```erlang
1> lists:module_info(module).
lists
2> lists:module_info(exports).
[{append,2},{reverse,1},{map,2},...]
3> lists:module_info(md5).
<<...>>
```

**Example 2** (module_info/0 returns all information):
```erlang
1> m:module_info().
[{module,m},
 {attributes,[{vsn,[...]}]},
 {compile,[{version,"8.0"}, ...]},
 {exports,[{fact,1},{module_info,0},{module_info,1}]},
 {md5,<<...>>}]
```

# Common Errors
- **Error**: Trying to define `module_info/0` or `module_info/1` manually in a module
  **Correction**: These functions are auto-generated by the compiler; defining them manually causes conflicts

# Common Confusions
- **Confusion**: Expecting `module_info(attributes)` to return data after stripping
  **Clarification**: After `beam_lib:strip/1`, the attributes list becomes empty

- **Confusion**: Expecting the `functions` key to only return exported functions
  **Clarification**: `module_info(functions)` returns all functions (including local ones); use `module_info(exports)` for only exported functions
