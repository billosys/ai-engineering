# Quick Definition

An OTP application uses a standard directory layout with five subdirectories — `doc`, `ebin`, `include`, `priv`, `src` — under a top-level application directory whose name may include a version number.

# Core Definition

Creating an OTP application consists mostly of setting up a standard directory structure and writing application metadata (Ch. 4, Section 4.1.1). The application directory is named after the application, optionally with a `-<version>` suffix (e.g. `tcp_rpc-1.0.2`) used when shipping to make code upgrades easier. The standard subdirectories are:

- **doc** — Documentation; the `overview.edoc` file goes here and the rest is autogenerated by EDoc.
- **ebin** — Compiled code (the `.beam` files) and the `.app` metadata file. Only `ebin` is strictly required.
- **include** — Public header files; any `.hrl` file that is part of the public API.
- **priv** — Odd bits distributed with the application (templates, shared objects, DLLs); located via `code:priv_dir/1`.
- **src** — Source code: `.erl` files, internal `.hrl` files, and other source files.

# Prerequisites

- **OTP application** — The directory layout is how an application is organized on disk.

# Key Properties

1. A top-level directory named after the application, optionally with a `-<version>` suffix.
2. Five standard subdirectories: `doc`, `ebin`, `include`, `priv`, `src`.
3. Only `ebin` is strictly required.
4. `ebin` holds `.beam` files and the `.app` metadata file.
5. Public `.hrl` files go in `include`; internal `.hrl` files go in `src`.
6. `code:priv_dir/1` returns the full path of the `priv` directory.

# Construction / Recognition

## To Lay Out an Application:
1. Create a top-level directory named after the application.
2. Create the `doc`, `ebin`, `include`, `priv`, and `src` subdirectories.
3. Put source code in `src`, compiled output and the `.app` file in `ebin`.

# Context & Application

The layout is universal: even people who know only plain Erlang use this structure, often without metadata.

- **Typical contexts**: Every OTP application on disk.
- **Common applications**: The `tcp_rpc` and `simple_cache` application directories.

# Common Errors

- **Error**: Putting the `.app` file somewhere other than `ebin`.
  **Correction**: The `.app` file belongs in `ebin` alongside the `.beam` files.

- **Error**: Putting public header files in `src`.
  **Correction**: Public `.hrl` files go in `include`; only internal headers belong in `src`.

# Common Confusions

- **Confusion**: Thinking all five subdirectories are mandatory.
  **Clarification**: Only `ebin` is strictly required; the others are conventional and can be omitted if unused.
