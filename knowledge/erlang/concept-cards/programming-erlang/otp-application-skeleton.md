# Quick Definition

The OTP application skeleton is the standard set of boilerplate files and directory structure a conforming OTP application needs, generated by `rebar create-app`.

# Core Definition

Running `rebar create-app appid=Name` "created the necessary boilerplate files and directory structure needed for a standard OTP application" ("Making an OTP Application"). The generated skeleton consists of an application resource file and the application-behaviour and top-level-supervisor modules, all placed under the project's `src` directory. The developer then adds their own modules to `src` and builds everything with `rebar compile`.

# Prerequisites

- **Rebar** — The skeleton is generated by the `rebar create-app` command.

# Key Properties

1. Generated by `rebar create-app appid=Name`.
2. Produces `src/<name>.app.src` — the application resource (metadata) file.
3. Produces `src/<name>_app.erl` — the application-behaviour callback module.
4. Produces `src/<name>_sup.erl` — the top-level supervisor module.
5. Source modules live under the `src` directory; compiled `.beam` files land in `ebin`.

# Construction / Recognition

## To Construct/Create:
1. From the project directory, run `rebar create-app appid=Name`.
2. Add your own modules (e.g., `Name.erl`) to the `src` directory.
3. Run `rebar compile` to build all files into `ebin`.

## To Identify/Recognize:
1. A `src` directory containing `<name>.app.src`, `<name>_app.erl`, and `<name>_sup.erl`.
2. The triple of resource file + `_app` module + `_sup` module is the signature of an OTP application skeleton.

# Context & Application

- **Typical contexts**: Starting any new Erlang project intended to be a standard OTP application.
- **Common applications**: Scaffolding a project before adding business-logic modules and publishing it.
- **Historical/stylistic notes**: The book demonstrates this with the `bertie` project; the `_app`/`_sup` split mirrors the OTP application and supervision-tree conventions covered elsewhere in the book.

# Examples

**Example 1** ("Making an OTP Application"): Generating the skeleton for the `bertie` project:

```
$ rebar create-app appid=bertie
==> bertie (create-app)
Writing src/bertie.app.src
Writing src/bertie_app.erl
Writing src/bertie_sup.erl
```

**Example 2** ("Making an OTP Application"): After scaffolding, a hand-written `bertie.erl` module is added to `src` and the whole project compiled with `rebar compile`, producing compiled output for `bertie.erl`, `bertie_app.erl`, and `bertie_sup.erl`.

# Common Errors

- **Error**: Placing source modules outside `src`, so `rebar compile` does not find them.
  **Correction**: Put all `.erl` files under the `src` directory generated by the skeleton.

- **Error**: Hand-writing the `_app` and `_sup` modules and the `.app.src` file.
  **Correction**: Generate them with `rebar create-app` so they follow OTP conventions.

# Common Confusions

- **Confusion**: Thinking the generated `_app`/`_sup` modules are placeholders to delete.
  **Clarification**: They are the real application-behaviour and supervisor modules required by a standard OTP application.
