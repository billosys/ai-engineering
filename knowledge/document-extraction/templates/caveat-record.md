# Caveat Record Template

Use with [validation and reports](../guides/10-validation-and-reports.md).
Repeat per issue and attach the ID to every affected map/record and per-use
decision. See the [PDF handoff](../examples/pdf-marker-handoff.md#caveats).

| Field | Value |
| --- | --- |
| Caveat ID / manifest / run | <stable ID and references> |
| Source / affected input and prepared snapshots | <IDs> |
| Category / short issue | <identity/lineage, capture, structure, media, locator, fidelity, verification coverage; concrete issue> |
| Affected source resources / spans / locator IDs | <exact locations, or unknown extent explicitly> |
| Affected outputs / sections / media / mappings | <paths and record IDs> |
| Observation / evidence pointer | <actual observation; missing or damaged content; log/excerpt/record> |
| Observer / evidence kind / coverage | <direct, operator-reported, inferred; inspected versus unchecked scope> |
| Uncertainty and alternatives | <what remains unknown; do not invent missing content> |
| Current handling | <preserved original, withheld mapping/split, retained reference, etc.> |
| Per-use impact | <requested use, scope and effect; readiness report reference> |
| Status / recorded date | <unresolved or resolved with evidence; date> |
| Resolution or re-entry check | <bounded inspection/input/repair; criterion that would change disposition> |
| Next actor if known | <responsible actor or unassigned> |

## Resolution History

| Date / run | Previous state | New observation and evidence | Changed disposition / remaining limits |
| --- | --- | --- | --- |
| <date/run or no resolution yet> | <state> | <evidence or none yet> | <state; affected checks rerun> |

Keep prior observations and snapshot associations when resolved. Do not remove
an issue from a later report without recording the evidence that resolved it.
