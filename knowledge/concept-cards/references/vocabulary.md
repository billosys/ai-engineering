# Concept Card Vocabulary

These terms are descriptive, reviewable vocabulary for the existing templates
and examples. They are not a final enum set, a schema grammar, or a command to
coerce an artifact into a value not justified by its evidence.

| Term | Meaning and boundary |
| --- | --- |
| concept card | One user-authored concept boundary and synthesis; it can reference finer-grained claims. |
| claim | An identifiable assertion whose support and lifecycle assessment can be scoped precisely. |
| source locator | An address into a source or prepared representation; an address alone is not support. |
| source span | The selected material and boundaries used for inspection. |
| source support | An assertion-to-span comparison for a claim, edge, or CQ coverage assertion. |
| prepared-source provenance | Snapshot, manifest, mapping, readiness, and caveat information supplied upstream by `document-extraction`. |
| evidence grade | Warrant assessment for the stated subject and use; it is not extraction confidence. |
| extraction confidence | Calibration about an extraction act and its scope; it is not truth or admission. |
| validation result | Structural-check observations and limits for declared records and references. |
| verification result/state | Semantic review observations and their scoped applicability; same-context review is not independent by label alone. |
| relationship edge | A separately identified relation with endpoint roles and edge-specific support; endpoint support does not warrant the relation. |
| competency question (CQ) | A requirement question with distinct coverage, answerability, and retrieval observations. |
| reconciliation result/state | A comparison and disposition for a named conflict; it does not replace validation or verification. |
| preservation decision | A disposition for prior value: preserved, superseded, rejected, or unresolved, with a recoverable rationale. |
| memory admission | A scoped reliance decision, not retention or a runtime memory write. |

`unassessed`, `partial`, `conflicting`, `inaccessible`, `unresolved`, and
`deferred` should remain explicit when applicable. They do not become success
states merely because a record exists.
