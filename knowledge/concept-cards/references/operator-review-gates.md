# Operator Review Gates

Use these gates when accountable judgment is needed beyond structural checking
or semantic audit. Record the authority, target revision, decision, evidence,
conditions, and re-entry trigger. A missing gate remains unassessed; it is not
implicitly approved.

| Gate | Operator decision | Minimum recorded basis |
| --- | --- | --- |
| Memory admission | Permit, reject, or defer scoped durable reliance. | Target/use, source support, evidence grade, validation, verification, reconciliation, preservation, and any required acceptance. |
| Conflict disposition | Accept a material reconciliation where alternatives affect intended use. | Alternatives, source comparison, rationale, unresolved consequences, and resulting references. |
| Preservation exception | Accept a deviation from the ordinary prior-value disposition or unresolved retention. | Unique value, affected revisions, evidence limits, rationale, and re-entry condition. |
| Material uncertainty | Decide whether incomplete evidence blocks use, requires a caveat, or must remain deferred. | Scope, missing/inaccessible evidence, risk to intended use, and next inspection. |
| Method exception | Approve an exception to the method's construct, evidence, or review expectations. | Exact exception, owner, duration/scope, rationale, and restoration or review condition. |

## Deferred Runtime Checks

The following remain future runtime work, not operator gates that this skill can
perform: graph-database or ontology-database closure, GraphRAG retrieval probes,
memory-runtime enforcement, CCDP service orchestration, and live-corpus
extraction. Recording an operator decision does not create those systems or
write to memory.
