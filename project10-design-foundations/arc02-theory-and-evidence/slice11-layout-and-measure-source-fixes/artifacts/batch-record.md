## Contract readback

The accepted Slice04 policy treats intrinsic, content-led composition as a
starting method and allows a justified fixed size or discrete query when the
task, content, user or output condition calls for it. The old query-removal
question is a diagnostic for the tested case, not a universal requirement.
Likewise, spatial primitives support reusable composition but do not prove
that every task fits their vocabulary, that different compositions are
consistent, or that markup and interaction semantics are correct. Preserve
the useful named patterns and examples while describing their limits.

An optional construction cannot guarantee an outcome: a `ch` measure depends
on the used font's “0” advance (and may use specified fallback metrics), not an
arbitrary character count; `auto-fit`/`minmax()` follow Grid track sizing; fixed
or preferred sizing can expose overflow whose behavior must be checked. A
finite content/viewport diagnostic identifies conditions worth inspecting;
passing those cases cannot prove behavior for all content, users or browsers.
Inheritance remains a CSS mechanism and is not prohibited by composition.

The current W3C material supports those technical distinctions: [CSS Sizing
3 §3.1](https://www.w3.org/TR/css-sizing-3/#preferred-size-properties), [CSS
Overflow 3 §3.1](https://www.w3.org/TR/css-overflow-3/#overflow-properties),
[CSS Grid 2 §§7.1–7.2](https://www.w3.org/TR/css-grid-2/#track-sizing), [CSS
Values 4 §6.1.1](https://www.w3.org/TR/css-values-4/#font-relative-lengths),
and [CSS Cascade 5 §7.2](https://www.w3.org/TR/css-cascade-5/#inheriting).
CSS Sizing 3 is currently published as a Working Draft; these contemporary
definitions are not historic source evidence.
