Combined bounded answers:
1. **Uniformity/design:** An ideal uniform model aims for coordinate differences
   to correspond consistently to observed perceived differences under named
   conditions. Oklab approximates that aim. It can inform candidate ramps/paths;
   check destination gamut/rendering and actual pairs. No step guarantees equal
   appearance across hue/context.
2. **Palette:** In lightness-perceptual, choose contextual `L_start`, `L_end` and integer `n>0`; compute `L_i=L_start+i(L_end−L_start)/n` for `i=0…n`. Apply chosen targets across intended hues with contextual C, then convert/check gamut and mapping, inspect rendering, evaluate actual foreground/background pairs and adjust. Oklab supplies candidate coordinates only; equal numeric L steps do not guarantee equal appearance.

3. **Conversion:** State model/encoding/reference; adapt whites when needed.
   Either use XYZ M1×XYZ → signed real cube root → M2, or decode encoded sRGB
   then combined A×linearRGB → root → B. Reverse B, cube, matching inverse;
   encode only for encoded output. Rounded coefficients yield approximate results.
4. **Chroma/saturation:** Oklab C=hypot(a,b) is exact in that coordinate system.
   CIE chroma/saturation use different brightness references; HSL/HSV labels
   are model-specific, with no universal C/L law.
5. **Colour/music:** This is a loose analogy only: a fitted 3D colour transform
   and 12-TET frequency ratios are different mathematics and do not imply equal
   visual/auditory intervals.
