file per style is not universal ([OpenType variations introduction](https://learn.microsoft.com/en-us/typography/opentype/spec/otvaroverview)).
Font resources are not ordinary end-user applications, but “static data/not
programs” must not imply no executable hinting instructions ([TrueType instruction-set introduction](https://learn.microsoft.com/en-us/typography/opentype/spec/tt_instructions)).

Serif/sans labels alone do not decide which actual italic/bold works. Keep true
face availability/synthesis visible. Distinguish heading semantics from CSS
appearance: choose HTML heading level from content structure, not desired font
size ([HTML headings](https://html.spec.whatwg.org/multipage/sections.html#the-h1,-h2,-h3,-h4,-h5,-and-h6-elements)).
`em` indicates stress; `strong` importance/seriousness/urgency, rather than merely
italic/bold styles ([HTML em/strong](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-em-element)).
Both may legitimately apply; CSS appearance is not the semantic definition.
Preserve source advice on breaks/keep-with-next as contextual output checks,
not universal browser pagination promises. Keep accessible structure/reading
order obligations explicit without claiming tested AT behavior.

**All/small caps:** preserve the real-versus-scaled-glyph distinction and useful
source examples. Paid status, every word-processor button, script-wide caps and
mandatory5–12% tracking/kerning are not universal technical rules. Source cognitive
and judicial explanations remain attributed accounts, not independent science
or legal findings; do not assert fatigue/word-shape causation as proven here.
CSS uppercase is language-sensitive and does not rewrite the underlying text
([CSS Text §2.1](https://www.w3.org/TR/css-text-3/#text-transform)); case distinctions
are not universal across scripts. Evaluate actual strings, fonts and spacing.

`font-variant-caps: small-caps` requests glyphs (OpenType `smcp`), not a guarantee
of genuine forms. `all-small-caps` also maps capitals (`c2sc`). Missing features
can produce synthesis; `font-synthesis: none` disables synthesis, including bold/
oblique as well as caps, and does not supply missing glyphs. Show the requested
caps declaration and synthesis guard as an optional scoped illustration; a
missing feature needs a truthful fallback and actual font/output inspection.
Support depends on font, application and script, not the paid/system label
([CSS Fonts4 capitalization §6.6](https://www.w3.org/TR/2026/WD-css-fonts-4-20261016/#propdef-font-variant-caps),
[synthesis §2.8](https://www.w3.org/TR/2026/WD-css-fonts-4-20261016/#propdef-font-synthesis)).
Use the current specification's actual sections; a draft is not a browser survey.

**Typographic color:** retain texture/density versus literal hue distinction.

intensity and colour-emphasis claims as source preferences/inferences. No fixed
palette, optical-comfort guarantee or one “strongest” visual mechanism. Actual
