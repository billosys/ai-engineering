# Runtime And Admission Boundary

## What Arc07 Did Not Implement

Project05 Arc07 creates no graph database, graph projection, GraphRAG flow,
vector store, embedding pipeline, retrieval endpoint, retrieval evaluation,
import automation, MCP server or tool, memory runtime, or memory-store write.
It also does not establish any access-control, update, retention, or deletion
behavior for a future system.

## What The Candidate Set Is Not

The ten cards are not a complete corpus, accepted knowledge base,
independently semantically verified record set, reconciled graph, preserved
prior-value collection, admitted memory, or runtime-ingested data set.
Candidate status and extraction self-checking cannot become any of those
states merely by packaging, projection, or retrieval.

## Separate Decisions Required Later

A downstream project must separately define and evidence:

1. the eligible record lifecycle for a review surface, import, and any memory
   admission decision;
2. a projection schema that preserves source and lifecycle fields;
3. operator questions, corpus snapshot, measures, and comparison protocol for
   retrieval evaluation;
4. explicit graph/retrieval/MCP ownership, access, operations, and failure
   behavior; and
5. any preservation, reconciliation, attribution, and retention decisions.

Until then, this handoff remains durable planning evidence and canonical-card
pointers only.
