## Progress, persistence and adaptation

### R01 — The method is more explicit, but its examples miss important task shapes

Both initial prompts require representative execution, inventory before judgment,
separate originals/verdicts/replacements, and meaningful checks. Both preparations
supply a complete record and exercised invalid examples. This is observable
implementation of the intervention, not merely a declaration of compliance.

However, T01's runnable example consumes a single-line format assertion;
T02's consumes a single-line query policy. They exercise identity/reference and
false-upgrade checks, not a full multiline assertion, an actual two-original
consistency comparison, or a structured edit composed back into a real file.
Some difficult cases are still instructions to work a case, rather than an
already demonstrated case. T02 case 3 says to work a dense navigation/actions
scenario; initial review F05 later finds that the returned scenario lacks a
specific task failure and observable transition.

**Interpretation:** Preparation is more concrete than the baseline, but its
coverage of likely failure modes is partial. Passing the supplied demo does not
show that the batch method handles the hard parts. This is evidence against
claiming that the bundle was fully applied and simply ineffective. It also
challenges the assumption that adding any worked example is enough.

**Interpretation:** The evidence is stronger for reactive repair than preventive

reliable application across a new batch or the next slice. That distinction is
more useful than calling all adaptation either successful or failed.

## Artifact utility: a newly reproduced packet defect

### R05 — T02 I02 contains six competing action registries

At `273deaba`, the [handoff](../../../project10-design-foundations/arc02-theory-and-evidence/slice04-layout-and-measure-exceptions/artifacts/correction-handoff.md) calls its JSON
an authoritative action registry but contains **six JSON array payloads**, each
with the same 25 action IDs, beginning after fence markers at lines 38, 1613,
3188, 4763, 6338 and 7888. Only one bare closing fence appears, at line 9027.
All six arrays are individually decodable and all six differ. Relative to the
first, later arrays change replacement strings for 2, 2, 2, 3 and 24 actions.
They are not presented as separately labeled historical snapshots.

The current [notes checker](../../../project10-design-foundations/arc02-theory-and-evidence/slice04-layout-and-measure-exceptions/artifacts/execution-notes.md), lines 82–83,
extracts `text.split('```json\n',1)[1].split('\n```',1)[0]`: it selects only the
first array. An in-memory probe replacing everything from the second marker
onward with invalid JSON leaves this extraction's result unchanged. This is a
reproduced **extraction blind spot**, not a claim that the full validator was
rerun or that any particular CSS replacement is now independently accepted.

The five additional arrays contain **384,778 bytes**. The handoff grew from
72,780 bytes at H1 to 472,636 at H2, while the result population stayed at 84.
This identifies specific duplication and competing authority, not merely a large
file. It can confuse a reader or later editor, and extra material falls outside
the checker-selected registry. Actual downstream implementation harm or elapsed
cost has not been measured. This belongs in the pending host review; the study
does not repair it or close/reopen a host ledger row.

**Interpretation:** The record-economy observation is mixed. Avoiding a huge
predecessor dataset in execution notes is an improvement in representation, but
duplication can reappear elsewhere. The promised current artifact and the subset
consumed by a checker must be considered together. Do not infer that all six
payloads are needed because the file passes a check aimed at the first one.

## Hypotheses, limits and next review

- **H1, recurrence prevention:** not established. The same failure types recur
  across the two treatment tasks and after expressly targeted corrections.
  Partial adherence and incomplete example coverage prevent separating an
  ineffective method from ineffective execution of it. T01 reaches accepted
  results; repair success and prevention are different observations.
- **H2, record economy and effort:** limited favorable evidence for removing
  inline predecessor datasets; contrary evidence from duplicated handoffs and
  current-summary drift. Net efficiency remains unknown. Do not adopt a broad
  improvement claim based on smaller notes or more controls.
- **Artifact-goal concern:** now has a directly reproduced misuse example plus
  useful counterexamples. Goal displacement at project scale remains unmeasured.
- **Quality floor:** independent host acceptance stayed scoped; T01 closed and
  T02 remains open. This research changes no host verdict. Finding problems
  before acceptance is valuable, but does not prove their prevention or full
  review coverage.

Task heterogeneity, censored endpoints, unequal criteria, unknown model/settings
and total effort, reused contexts, order/learning effects, reviewer expectations,
and a bundled intervention limit attribution. The same CDC authored and assesses
the method. No statistical significance, component effect or causal percentage
is claimed. The new payload inspection is an exploratory observation within the
predeclared artifact/validation lens, not retrospective rescoring of Case01.

For the pending T02 review, inspect the **complete delivered handoff**, including
unique current registry, all visible replacement versions and composition, before

## Reproduction and validation scope

Run the following read-only Python from the planning worktree. It reproduces

```python
import subprocess,json
ROOT='project10-design-foundations/arc02-theory-and-evidence/'
RUNS={
 'B':('slice02-nonlinear-colour-pipeline',['fd73d993','73c8180b','590b263c','6a016960']),
 'T01':('slice03-token-system-conventions',['2eee292c','578e68f8','c2f36b62','c51a21ad','3817d83c']),
 'T02':('slice04-layout-and-measure-exceptions',['742de371','7eb7a38e','273deaba'])}
def git(*args):return subprocess.check_output(['git',*args])
rows=[]
for run,(name,revs) in RUNS.items():
 paths=['ledger.md','closing-report.md']+['artifacts/'+n for n in ['claim-results.jsonl','correction-handoff.md','execution-notes.md']]
 paths += ['artifacts/'+n for n in (['colour-conversion-proof.md','numerical-reconciliation.md'] if run=='B' else ['occurrence-inventory.jsonl','source-comparison.md'])]
 for i,rev in enumerate(revs):
  blobs={p:git('show',rev+':'+ROOT+name+'/'+p) for p in paths}
  row={'run':run,'return':i,'revision':git('rev-parse',rev).decode().strip(),'packet_bytes':sum(map(len,blobs.values())),'notes_bytes':len(blobs['artifacts/execution-notes.md']),'notes_lines':len(blobs['artifacts/execution-notes.md'].splitlines()),'jsonl_rows':len(blobs['artifacts/claim-results.jsonl'].splitlines()),'claims_bytes':len(blobs['artifacts/claim-results.jsonl']),'handoff_bytes':len(blobs['artifacts/correction-handoff.md'])}
  rows.append(row)
for r in rows: print(r['run'], r['return'], r['packet_bytes'], r['notes_bytes'], r['handoff_bytes'])

import re
path = ROOT + RUNS['T02'][0] + '/artifacts/correction-handoff.md'
text = git('show', '273deaba:' + path).decode()
markers = list(re.finditer(r'^```json\n', text, re.M))
arrays = []
for marker in markers:
    tail = text[marker.end():]
    array, end = json.JSONDecoder().raw_decode(tail)
    arrays.append((array, len(tail[:end].encode())))
first = {a['action_id']: a for a in arrays[0][0]}
assert len(markers) == 6 and len(first) == 25 and all(len(a) == 25 for a, _ in arrays)
assert len(re.findall(r'^```$', text, re.M)) == 1
assert len({json.dumps(a, sort_keys=True) for a, _ in arrays}) == 6
for i, (array, size) in enumerate(arrays, 1):
    current = {a['action_id']: a for a in array}
    assert set(current) == set(first)
    changes = sum(first[k]['replacement'] != current[k]['replacement'] for k in first)
    assert changes == [0, 2, 2, 2, 3, 24][i-1]
    print('registry', i, 'bytes', size, 'changed replacements', changes)
extract = lambda t: json.loads(t.split('```json\n', 1)[1].split('\n```', 1)[0])
mutated = text[:markers[1].start()] + '```json\nINVALID JSON\n```\n'
assert extract(text) == extract(mutated)
assert sum(size for _, size in arrays[1:]) == 384778
print('Later-payload mutation leaves first-registry extraction unchanged.')
