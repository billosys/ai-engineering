## Summary

The current Makefile builds 12 installable skill zip archives. I rebuilt those
archives with `make all` on 2026-08-29 and scanned Markdown inside each package
root for references that do not resolve from the unzipped package context.

The scan found 145 actionable package-context misses across the 12 zips:

| Classification | Count | Meaning |
|----------------|------:|---------|
| bundled-reference | 104 | The intended target is bundled, but the authored path uses source-root or otherwise wrong package-relative semantics. |
| source-clone-reference | 38 | The target exists in the source clone but is not bundled in the zip under the referenced path. |
| repo-only/provenance | 3 | The target is intentionally repo/planning/provenance material and should not be required to resolve inside the zip. |
| example-project path | 0 | No confirmed package miss in this run required this category. |
| external URL | 662 | URL references were observed and classified as outside package-path validation. They are not package misses. |
| parser false positive | 1081 | Broad scanner captures from examples, code snippets, placeholders, and non-file tokens. These should be validation exceptions or avoided by a stricter parser. |

Main finding: the package path problem is not evenly distributed. Most
actionable misses come from skill entry points that still name source-clone
paths such as `knowledge/js/guides/...`, while the package layout strips that
prefix and places guides under `<skill-name>/guides/...`.

## Packaging Model

`collaboration-framework.zip` is staged from the explicit `CF_FILES` list into
`build/collaboration-framework/`. Its package root contains `SKILL.md`,
selected `docs/**`, and selected `templates/**`.

Every per-domain bundle is built through `pack_skill`. The macro stages exactly
one skill file plus the domain's sibling `guides/` directory:

```text
<skill-name>/<skill-file>
<skill-name>/guides/**
```

That means source paths like `knowledge/js/guides/01-core-idioms.md` are valid
in the cloned repository but package-invalid unless rewritten to
`guides/01-core-idioms.md` or resolved by a staging-time transform.

## Scan Method

Temporary scanner used during this slice:

```sh
python3 /private/tmp/package_path_audit.py \
  /Users/oubiwann/lab/billosys/ai-engineering \
  collaboration-framework.zip rust-guidelines.zip go-guidelines.zip \
  cpp-guidelines.zip javascript-deno-guidelines.zip erlang-guidelines.zip \
  cobalt-guidelines.zip visual-design-system.zip tailwindcss.zip \
  deno-js-linter.zip biome-js-linter.zip biome-linter.zip \
  > /private/tmp/package_path_audit.csv
```

The scanner:

- opens each zip with Python `zipfile`;
- scans only `*.md` files inside the package;
- extracts Markdown inline links, reference definitions, and inline-code tokens
  that look like repository paths;
- resolves relative paths from the Markdown file's location inside the package;
- treats URL schemes as external references;
- checks whether unresolved package targets exist in the source clone;
- classifies misses into the Slice 01 vocabulary.

Important limitation: this was intentionally a diagnosis script, not the final
gate. Its regex pass over inline examples is broad, so the `parser false
positive` bucket is large by design. Slice 02 should replace this with a
purpose-built validator that can ignore fenced code, placeholders, and
non-path identifiers deterministically.

## Path Contract Proposal

### Source Clone

Source-clone references may use repository-root paths when the document is
describing repository maintenance, extraction provenance, workbench material,
or cross-skill development context. Those references must be labelled in prose
as source-clone-only, repo-only, or provenance-only when the same document is
also shipped in a zip.

### Package Root

Packaged documents must resolve reader-facing bundled references from the
unzipped package root or from the current document location. For per-domain
skills, bundled guide references should be authored or transformed to:

```text
guides/<path>
```

For `collaboration-framework`, bundled framework references should stay inside:

```text
docs/<path>
templates/<path>
SKILL.md
```

Relative links from `docs/pm/*` to `docs/PROJECT-MANAGEMENT.md` must use
document-relative paths such as `../PROJECT-MANAGEMENT.md` in the package.

### Repo-Only and Provenance Material

References to `workbench/**`, `docs/dev/**`, extraction metadata, source
corpora, tool scripts, planning artifacts, and placeholder paths such as
`knowledge/<slug>/SKILL*.md` should not become hard package failures. They
should be explicitly marked in source text and represented in validation as
classified exceptions.

### External URLs

External URLs are outside package path resolution. A later validator may check
syntax, but it should not require network access or URL liveness for this path
contract.

### Parser False Positives

The final gate should parse Markdown with enough structure to skip fenced code,
examples, placeholder tokens, headings, anchors, and non-path identifiers. The
diagnosis script's 1081 false positives are evidence that a raw regex scan is
not adequate as a hard-fail gate.

## Disposition by Fix Type

| Fix type | Apply to | Recommendation |
|----------|----------|----------------|
| source edit | Small, source-true path corrections where one spelling works in source and package, especially `docs/pm/*` links and guide-local links. | Prefer source edits when they improve the source clone without adding package jargon. |
| staging-time transform | High-volume package-only rewrites such as `knowledge/<domain>/guides/...` to `guides/...` in packaged `SKILL.md` files. | Likely best default for mature skills; avoids churn in source prose that is semantically source-root-oriented. |
| package layout change | Cases where readers need material that is truly absent, not merely referenced with the wrong prefix. | Use sparingly. Do not expand packages to include workbench, source corpus, extraction metadata, or dev planning by default. |
| validation exception | Explicit repo-only/provenance paths, placeholders, URLs, anchors, and parser false positives. | Require a reasoned class; do not allow an unclassified miss bucket. |
| CCDP package work | Any reference under `protocols/ccdp/**` or future protocol package entry point. | Leave to Arc 03 unless Slice 02 decides the validator must reserve a CCDP package class now. |

## Slice 02 Implications

Slice 02 should design the validation gate around this contract rather than the
temporary scanner. The next slice should decide:

- exact validator name and Make target;
- whether package-invalid `bundled-reference` and `source-clone-reference`
  rows hard-fail immediately or start as warnings while Arc 02 performs
  harmonisation;
- the allowlist schema for `repo-only/provenance`, `example-project path`,
  `external URL`, and parser exceptions;
- whether staging-time transforms live in Makefile shell, a checked-in script,
  or a small package-manifest data file;
- whether the gate should scan only generated zips, or also the staging
  directory before zipping.

already matches the findings: convert this contract into Make/Bash-friendly
validation requirements and decide warning versus hard-fail gates.
